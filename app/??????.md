# 数据接口说明（标准化）

- `schema`：`resume-tracker`
- `schema_version`：`1`
- 适用范围：本地网页版（含发行版）

## 一、数据保存在哪

所有数据都保存在程序文件夹内的 `data` 目录，不会写到别的地方：

```
data/applications.db         主数据（SQLite）
data/change_log.jsonl        改动日志，只追加、含删除前的完整数据
data/backups/<时间戳>/        每次启动自动备份的一份（见下）
```

更新程序时，只替换代码文件（`launcher.py`、`server.py`、`core/`、`api/`、`web/`），**保留 `data/` 目录**，数据不会丢。

### 启动自动备份

**每次启动程序都会先把数据备份一份**，放在 `data/backups/<时间戳>/`：

| 文件 | 是什么 |
| --- | --- |
| `applications.db` | 主数据的**一致性快照**——走 SQLite 自己的在线备份接口，不是拷文件，程序开着也安全 |
| `change_log.jsonl` | 改动日志的副本（只拷完整的行，最后写了一半的那行丢掉） |
| `个人画像.json` | 有才拷 |
| `manifest.json` | 这一份是什么时候备的、多大、多少条、校验过没有 |

- 每次启动新建一个文件夹，**不覆盖、不自动清理**；想清就整个 `data/backups/` 删掉，没有副作用。
- 备份失败**不会拦住程序启动**（原因写 `logs/backup.log`），也不会留下半成品文件夹：
  先写到 `.tmp-<时间戳>/`，校验通过（`PRAGMA quick_check` + 数行数）才改名成正式的。
- 双击快捷方式、`启动（调试窗口）.cmd`、`启动（安全模式）.cmd` 都会备份——只要新起了一个服务就备份一次。

## 二、标准化数据包

「导出 → JSON 备份」导出的就是标准化数据包，结构如下：

```json
{
  "schema": "resume-tracker",
  "schema_version": 1,
  "app_version": "1.0",
  "exported_at": "2026-09-09 22:00:00",
  "applications": [],
  "stages": []
}
```

| POST | `/api/heartbeat` | **桌面模式**：页面还开着的心跳（**2026-10-10 起：页面加载后立即发一次，之后每 5 秒一次**；GET 也支持）。**必须带上外壳控制端口** `?shport=<端口>`——服务端只认当前窗口那个页面。返回 `{"ok":true,"accepted":<bool>}`；端口对不上会被忽略（不改心跳时间戳） |
| POST | `/api/attach` | **桌面模式**：**新窗口接管后端**（**2026-10-10 加**）。启动器开新窗口前发现端口上已有后端时，先发 `{"shport": <新窗口的外壳控制端口>}`：后端把「当前归属」原子地换成新端口、顺手清掉「正在关闭」倒计时并记一次心跳，返回 `{"ok":true}`。**接管失败**（后端已决定退出 / 端口非法 / 请求方太旧不支持）返回 `{"ok":false}`，此时启动器**不会**搭这趟车，等端口真空后自己起一个——这是"关窗后立刻重开变成僵尸窗口"那个 bug 的修法 |
| POST | `/api/closing` | **桌面模式**：页面正在关闭/刷新（`sendBeacon` 只能发 POST）。**必须带上外壳控制端口** `?shport=<端口>`，服务端只认窗口那个页面发的；别的页面发的会被忽略（返回 `{"ok":true,"accepted":false}`） |
| POST | `/api/shutdown` | **桌面模式**：优雅退出程序（浏览器外壳模式下的「退出」按钮调它）。**无边框窗口里的「退出」不走这条**，而是直接调启动器的控制端口（见下节），这样后端已经死了也能真的关掉窗口 |
| PUT | `/api/profile` | **保存个人画像**（2026-09-25 加）。只接受白名单字段；**主专业为空会被拒绝**（400 + `error`）；写入走「临时文件 + 替换」，不会留半截文件 |

| `server_time` | 服务端当前时间 |
| `stats` | 统计口径算出来的汇总（见 `core/stats.py`） |
| `notes` | 备忘录 |
| `resumes` | 简历：**只含元信息**（id / 标题 / 是否默认 / `rev` / 时间），正文按需 `GET /api/resumes/<id>` 取（2026-10-10 加，免得每次刷新都传几十 KB 正文） |
| `backup` | **本次启动**做的那次备份（见下一节） |

### state 里的 backup 字段

`GET /api/state` 的 `backup` 是**本次启动**做的那次备份：

```json
{"time": "2026-01-01 09:00:00",
 "dir": "…\\data\\backups\\2026-01-01_090000",
 "db_bytes": 123456, "db_rows": 12, "changelog_lines": 34,
 "profile": true, "ok": true, "reason": "startup"}
```

首次运行（还没有库）或备份失败时为 `null`。

### 关闭信号的来源校验 + 后端归属接管（`/api/closing`、`/api/attach`）

启动器开窗口时会把**外壳控制端口**写进地址（`&shport=NNNN`），又通过 `--shell-port` 把同一个端口
告诉服务端。页面关闭时把它带回来（`/api/closing?shport=NNNN`），服务端对得上才认。

**为什么**：关闭信号会在 15 秒宽限期后让服务退出。以前不带校验，于是任何别的页面
（你在浏览器里打开 `127.0.0.1:8768` 瞄一眼、无界面浏览器抓页面做自检）一关，就可能把**正在用的**
程序带走——而窗口的心跳是 20 秒一次，正好卡在 15 秒宽限期的竞态上。

**2026-10-10 又补了两件事**（起因：关掉窗口后**立刻**重开，新启动器看到端口还有响应就搭了
上一个正在退出的后端的车，15 秒后那个后端自己退了，页面变成连不上后端的僵尸窗口）：

1. **心跳改成「加载即发 + 每 5 秒」**（原来是 20 秒一次、且要等第一拍）。宽限期是 15 秒，
   20 秒的心跳**永远来不及**给后端续命，"刷新不会误退"那句话在旧代码里其实是不成立的。
2. **搭车改成握手接管**：启动器不再只 `ping` 一下端口就复用，必须先 `/api/attach` 成功才算复用；
   接管成功 = 归属换成新窗口的 `shport` + 清掉 `closing` 倒计时 + 记一次心跳。接管不成（后端已经在退、
   或那是旧版本/别的程序占着端口）就**等端口真空后自己起一个**。同时，那个迟到才到的「旧窗口关闭信号」
   因为归属已经换成新端口，会被忽略——不会把新窗口的后端关掉。

**窗口自己说了算的关闭**（无边框窗口的「退出」）：页面直接调启动器的控制端口
（`POST http://127.0.0.1:<shport>/ {"action":"close"}`），不再依赖后端 `/api/shutdown`——
后端已经死了的那次（页面显示"连不上本地程序"）也能真的关掉宿主窗口，不会留下一个看不见的进程。
浏览器外壳模式（没有 `shport`）才退回老路（`/api/shutdown` + `window.close()`）。

`--shell-port` 没传（浏览器外壳模式，或直接跑 `server.py`）时不校验，保持老行为。

## 五、兼容与升级

- 导入时**按字段名读取**，多余字段自动忽略。
- 缺少的字段使用默认值，不会导致导入失败。
- `schema_version = 1` 的字段会保持向后兼容；如果未来结构有变化，会提升版本号并提供自动迁移。
- 新增字段不会影响旧数据，旧版本导出的数据可以导入新版本。
