> 规矩：每一段来自外部的实现都必须能追溯到**固定提交**，并保留下游许可义务。
> 目标系统：本仓库（`app/`，3.0）。约束：**零依赖 + 无构建步骤**不得破。

## 三、许可义务与红线

- 三个采纳来源**均为 MIT**，允许商用与闭源分发。复制代码段时**保留原版权声明与许可文本**。
- **GPL / AGPL 一律不进本方案**（闭源分发义务冲突）。
- 资源类（字体、图标、截图）的许可**单独核查**，不因为"仓库是 MIT"就推定全部资源可商用。
- `dsh-resume` 是 **开发工具 宿主插件**，其工作台 UI（React + `window.__ModuleLoader__`）、
  主对话镜像、Agent 工具注册**一律不迁移**；只借鉴算法思路，不搬宿主耦合代码。

## 四、"零依赖"如何验证（不靠自觉）

采纳后必须能证明**发布包没有引入 Node / React / npm / 构建步骤**：

1. `python tools\test_architecture.py` —— core 只许标准库；
2. `python tools\test_data_safety.py` —— 发布包内容审查（含离线依赖包完整）；
3. 人工核对：`app/requirements.txt` 不新增条目；`app/web/index.html` 仍是单文件、无外部 CDN 引用；
4. 断网启动一次，界面与导出均可用。

## 五、与用户提供模板的关系（非第三方来源）

用户提供的 `resume-template-source.pptx` 是**版式规格**，不是代码来源，
许可上属于用户自有资产；其脱敏模板与版式参数见
`<tools>\resume-template\TEMPLATE.md`。
该 PPTX **不进入发布包**（既是隐私要求，也避免引入 PPTX 解析/渲染依赖）。
