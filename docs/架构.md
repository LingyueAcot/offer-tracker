# 架构（3.0）

> 一页说清：谁负责什么、数据怎么走、哪些边界不能越。
> 具体硬规则在根目录 `AGENTS.md`，取舍理由在 `代码规范.md`，操作细节在 `../开发记录`。

## 一、进程拓扑

```text
双击 app\应届海投管理.lnk  （或 app\启动（调试窗口）.cmd / 启动（安全模式）.cmd）
        │
        ▼
  launcher.py ── 单实例互斥体 → 探测端口 → pythonw 拉起 server.py
        │                                   │
        │ 页面上带 ?shell=borderless&shport= │ 先备份，再 init_db()
        ▼                                   ▼
  pywebview 窗口 + WebView2          server.py  http://127.0.0.1:8768
        │  fetch /api/*  ▲                  │
        └────────────────┘                  ▼
                                     data/applications.db（SQLite）
                                     data/change_log.jsonl（只追加）
                                     data/backups/<时间戳>/（每次启动一份）
```

| 谁 | 职责 | 不该做什么 |
| --- | --- | --- |
| `launcher.py` | 单实例、探测端口、起服务、开窗口、无边框补丁、接管窗口消息、窗口位置记忆、HTTP 窗口控制通道 | 不碰业务数据（**2026-09-24 起代码里已无例外**：原来每次启动会去删 `data/browser_profile`，那是 2.0 Edge 外壳的遗留、对 3.0 纯属空转，已删除） |
| `server.py` | **入口**：启动编排、`Handler`、4 个 `do_*`、4 条域链、HTTP 输出工具 | 不画界面、不开窗口；**新业务不放这里** —— 纯规则去 `core/`、读写库的用例去 `services/` |
| `services/` | **编排层**（2026-09-25 新增）：每个域一个模块，放「读 → 算 → 写 → 记审计」整套用例（投递/宣讲会/调研/state/桌面生命周期/画像/审计/备忘录） | **不 import `server`**（`tools/test_architecture.py` 用 AST 盯着）；不自己 `sqlite3.connect`（走 `store`）；不含 HTTP 细节 |
| `api/` | HTTP 路由，按域拆成 7 个 mixin（静态文件 / core / desktop / apps / notes / talks / io），共 39 条路由 | 只做参数与响应；**业务动作走 `services/`**，不要从 `server` 拿；不许模块级依赖 `server`（硬规矩 R9）；**同一个 mixin 里不许有同名方法**（R10，2026-09-27 加） |
| `store.py` | **数据访问唯一出口**：连接 + 事务 + 行映射 | 不含业务规则；**只有它（和 `backup.py`）能 `sqlite3.connect`** |
| `winenv.py` | **Windows 环境（2026-09-27 新增）**：DPI 感知、显示器可用区域与缩放、物理↔逻辑像素换算 | **叶子模块**：只依赖标准库，不许 import 项目里任何模块（硬规矩 R11）；`launcher.py` 与诊断报告共用这一份 |
| `core/` | **纯函数**：阶段推导、派生字段计算、统计口径、宣讲会解析、**宣讲会同步的合并判断**、调研解析、Excel/数据包规则 | 不 import `server`/`store`/`services`；不碰 DB / 网络 / 文件（`tools/test_core.py` + `test_architecture.py` 用 AST 盯着） |
| `schema.py` | **建表 / 老库补字段**（唯一允许改表结构的地方） | 不管连接生命周期；由 `init_db()` 调，而 `main()` 已经先备份过 |
| `backup.py` | 启动时把数据复制一份到 `data/backups/` | 不阻断启动、不改原数据 |
| `web/index.html` | 界面与交互（单文件，只通过 `/api/*` 通信） | 不直接读文件、不重复推导后端已给的派生字段 |

> **依赖方向只有一个**：`server.py → api/ → services/ → store.py / core/`。
> 下面不许回头叫上面。这条由 `tools/test_architecture.py` 的 10 条硬规矩盯着（`[WATCH]` 那 1 条
> 是**有意留下的尾巴登记**，见该文件注释与 `docs/架构.md` 的「S4 收尾说明」）。

## 二、数据流

**读**：页面 `load()` → `GET /api/state` → 一次拿全量 → `applyState()` → `render()` 整体重画。
**写**：页面 `api(method, url, body)` → server 写库 → `log_change(...)` → **返回完整 state** → 前端整体覆盖 `S`。

三条不能破的约定：

1. 所有写操作都要 `log_change(...)`，否则改动日志不完整（删除也要记，含删除前的完整数据）。
2. 派生字段（`derived_status` / `current_stage` / `current_result`）由后端算，前端只读不算。
3. 一次写操作返回完整 state，前端不做增量合并。

## 三、数据生命周期（最要紧的一段）

- **唯一真实数据**：`data/applications.db` + `data/change_log.jsonl`，没有第二份。
- **每次启动先备份**：`main()` 在 `init_db()` **之前**调 `backup.run_startup_backup()` →
  `data/backups/<YYYY-MM-DD_HHMMSS>/`。不覆盖、不自动清理、可整个删掉。
  备份要么完整要么不存在（先写 `.tmp-*`，`PRAGMA quick_check` + 数行数过关才改名）。
- **结构变更只有一处**：`schema.py` 的 `ensure_schema()`（`PRAGMA table_info` 判断后 `ALTER TABLE`）。
- **退出链路**：窗口页面关闭 → `beforeunload` 发 `/api/closing?shport=<外壳端口>` → server 只认这个端口
  （`--shell-port` 由启动器传入）→ 看门狗等 15 秒、没有新心跳就退出。别的页面发的关闭信号一律忽略。
  **发这个信号的有两方，两条路都带 `shport`、缺一不可**（2026-09-24 修）：
  ① 页面的 `beforeunload` 用 `sendBeacon` 发；② 启动器在窗口关掉之后自己也发一次
  （`launcher.py` 的 `post(actual_port, "/api/closing?shport=…")`）。
  原来 ② 漏带了 `shport`，被服务端判成"别的页面"直接忽略、日志却写「已通知服务」——
  因为 `_raw_post` 只要 `recv()` 不报错就返回 `True`、**不看状态码**。改关闭链路要两条一起看。
  别的任何地方都不许改表结构。
- **用户数据目录不许做实验**：要试就复制一份（`test_desktop_exit.py`、`test_backup.py` 都是这个套路）。

## 四、边界红线

| 规则 | 为什么 |
| --- | --- |
| `server.py` / `launcher.py` / `backup.py` / `core/` 只用标准库；前端不引框架、CDN、外链字体 | 这个程序靠「复制文件夹就能用、双击就跑」活着 |
| **纯逻辑一律放 `app/core/`**，`server.py` 只导回来用 | 放 core 才能不起服务就测（`tools/test_core.py`）；两条结构检查防它被抄回 server.py |
| 没有构建步骤：改完 `web/index.html` 保存刷新就生效 | 同上；出现「要先 build」就说明走错路了 |
| 入口路径不许改名挪位：`launcher.py`、`server.py`、`web/index.html` | 快捷方式、两个 `.cmd`、自检脚本都按这几个路径找 |
| `browser_profile/` `webview_profile/` `logs/` 不放 `data/` 里 | 缓存几十 MB，混进数据目录会让「复制 data 备份」又慢又大 |
| 加接口 → 同步 `app/数据接口说明.md`；加自检 → 同步 `tools/README.md` | 文档和代码一起改，别留给下一个人猜 |
