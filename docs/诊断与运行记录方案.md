## 〇、先说一个我查出来的**真盲区**

你说"这是我获得其他机器运行数据的途径"——问题比你想的严重一点：

**`launcher.py` 第 337-338 行，把服务端的输出直接丢进了垃圾桶：**

```python
subprocess.Popen(args, ..., stdout=subprocess.DEVNULL, stderr=subprocess.DEVNULL)
```

意思是：**`server.py` 一旦崩溃，它的错误信息（Python traceback）是凭空消失的。**
对方机器上程序半路挂掉，你手里**一条线索都不会有** —— 只能靠对方口述"就……突然没了"。

现在有日志，但都不够用：

| 现在有什么 | 记了什么 | 缺什么 |
| --- | --- | --- |
| `logs/launcher.log` | 启动过程、窗口事件、**启动器自己**的异常 | **服务端（业务代码）的异常一条都没有** |
| `logs/backup.log` | 每次备份成功/失败 | 只有备份 |
| `startup-log.txt` | 启动脚本选的 Python 路径 | 只有一行 |
| —— | —— | **没有任何"运行环境"记录**（系统版本、屏幕缩放、显卡、WebView2 版本…） |

**屏幕缩放（DPI）那条特别值得记**：上次那个"最大化下面一条黑横条"的 bug，
只在**缩放不是 100%** 的机器上看得见 —— 你这台电脑 96 DPI（100%）永远复现不了。
如果当时日志里有 DPI，一眼就能锁定。

## 一、要做的四件事

### ① 把服务端的输出接回来（**这是根上的修复**）

`launcher.py` 起服务端时，把 `stdout` / `stderr` 从"丢掉"改成**写进 `logs/server.log`**。
这样服务端任何打印、任何没被捕获的异常，都会留在文件里。

### ② 每次启动写一份「运行环境快照」

新增 `data/runtime.log`，**每次启动追加一段**（不是覆盖，能看出历史）：

```
==================== 2026-09-25 14:30:12 启动 ====================
应届海投管理 1.1 · 个人版 · 桌面模式 · 外壳=pywebview · 端口=8768
系统        Windows 11 (10.0.26200) 64 位
Python      3.12.8 (64 位)  %USERPROFILE%\AppData\Local\Programs\Python\Python312\pythonw.exe
屏幕        1920 x 1080 · 缩放 96 DPI (100%) · 1 个显示器
WebView2    152.0.4191.66
数据        投递 66 · 进展 76 · 阶段 14 · 宣讲会 130 · 备忘 1
启动备份    成功（data\backups\2026-09-25_143012）
```

> 这些全靠标准库拿：`platform` + `ctypes`（屏幕/DPI）+ `winreg`（WebView2 版本）。
> **不破"零依赖"** —— 我已经在这台电脑实测过，都能拿到。

### ③ 集中记「错误日志」

新增 `data/error.log`，只在**出问题**时写：

- 服务端每条路径（GET/POST/PUT/DELETE）抛异常 → 记完整 traceback；
- 后台线程（同步、看门狗）崩了 → 记（用 `threading.excepthook`，现在没装，等于哑的）；
- 启动器异常也**顺手复制一份**进去（原来的 `launcher.log` 照旧写，不影响任何现有行为）。

为什么要单独一个文件：出问题时**你不需要在 2000 行日志里翻**，直接看这个。

### ④ 一键导出「诊断报告」（你要的那个"途径"）

界面：右侧栏 📖「说明」弹窗里新增一节，**导出面板**里也加一个按钮。

点一下 → 下载一个 `诊断报告_20260925_1430.txt`（**一个文件，发给群/微信都方便**）：

```
应届海投管理 诊断报告
生成时间：2026-09-25 14:30
版本：1.1 · 个人版

【运行环境】    ← 上面那份快照
【文件清单】    logs/launcher.log 12.3 KB（最后修改 14:28）
                logs/server.log   3.1 KB
                data/error.log    0 B
【错误日志】    ← error.log 全部（这种文件通常很小）
【启动器日志·末尾 400 行】
【服务端日志·末尾 400 行】
```

**为什么只取"末尾 N 行"**：日志会一直长，全发给你的话可能几 MB，微信都传不动；
而且**出问题的那一段一定在最后**。

**同时**：说明弹窗里加一句"日志文件夹在哪"，加一个按钮直接打开 `logs` 文件夹
（想发原始文件的人也能发）。

## 二、一个必须你拍板的问题：报告里要不要带你的投递内容？

这是这个功能唯一的**隐私风险**，我不想替你决定。

日志里**会**出现你的数据（现有日志就是这样，没法避免）：同步会记「更新了哪家公司」、
改动记录会记「新增投递：某某公司 · 某某岗位」。

**两种做法：**

**A. 原样导出（推荐）**
报告里会有公司名、岗位名。**好处**：你看得懂、能判断对方卡在哪一步，诊断效率最高。
**风险**：这份文件发出去（发给你自己没问题；万一发到群里）会带你的求职信息。

**B. 自动打码后再导出**
把公司名、岗位名、个人画像里的关键词，以及**文件名里的用户名**
（`%USERPROFILE%\...` 这种）都替换成 `【已隐去】`。
**好处**：可以随便发。**代价**：诊断信息少一大截 —— 有时"卡在哪家公司"恰恰是关键线索。

> 我的建议：**选 A**，但报告抬头印一行醒目提示：
> 「本文件含你的投递记录，请只发给你信任的人」，并且**默认只发给你自己**。
> 打码（B）做成第二个按钮（"导出（隐去公司名）"），需要时再用。

**你来选：A / B / 两个都要（推荐 A 默认 + B 备选）。**

## 四、怎么做验证（做完给你看数字）

| # | 验什么 | 拿什么证明 |
| --- | --- | --- |
| 1 | **服务端崩溃不再凭空消失** | 造一个必然抛异常的场景（临时给 server.py 插一句 `1/0`，或用一个坏请求触发），确认 `logs/server.log` + `data/error.log` 里**真的有 traceback**，验完删掉那行 |
| 2 | 环境快照真的写进去了 | 打开 `data/runtime.log` 看这一段；重点确认 **DPI / 缩放** 有值（上次那个 bug 就靠它） |
| 3 | 报告能一键下载 | 点按钮拿到文件，格式、编码（UTF-8 BOM，记事本能直接打开）都对 |
| 4 | **报告里绝不含数据库内容** | 一条自动检查：报告文本里不许出现 `SQLite format`、不许出现几条只存在于库里的记录特征串 |
| 5 | 打码（如果选 B）真的打干净 | 拿你的真公司名/画像关键词当输入，断言报告里搜不到 |
| 6 | 截断逻辑对 | 造一个 10000 行的假日志，确认只取末尾 400 行、且报告总大小有上限 |
| 7 | **升级包不含新日志** | `升级自检` 24 项 + `test_data_safety.py` 9 项全过 |
| 8 | 老库/老配置升级后照样能用 | 跑 `升级自检`（它会把库退回老结构再升） |

调试时**不改你的真数据**；要造异常一律在副本上。

## 六、大白话总结

**你现在的问题**：程序在别人电脑上出毛病，你手里什么都没有——因为**服务端崩溃时的报错被代码丢掉了**（这是真 bug，不只是"缺功能"）。

**做完之后**：对方点一下「📖 说明 → 导出诊断报告」，会把**系统版本、屏幕缩放、显卡、Python 和 WebView2 版本、数据量、最近的错误和日志**打成一个 txt 发给你。以后再有"我这边打不开/白屏/闪退"，你看一眼报告基本就能定位。

**顺带修掉**：那个"崩溃报错被丢掉"的真 bug；以及服务端起不来时，提示框里会**直接带上错误原因**，而不是只说一句"程序没能启动起来"。

**需要你拍板的只有一件**：报告里要不要带公司名和岗位名（我建议带，但只发给你自己；打码版做成备选按钮）。
