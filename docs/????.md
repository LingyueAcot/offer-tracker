# 代码规范设计说明

> 这份文件解释**为什么这么定**；具体硬规则写在根目录 `AGENTS.md` 和各目录的 `AGENTS.md` 里，
> 这里不重复（规则单处维护）。参考对象是 `<workspace>\dsh-desktop-main`（开发工具 Desktop）——
> 但**只抄治理方法，不抄技术栈**。

## 一、设计出发点

开发工具 Desktop 是 Electron 宿主：多进程特权边界、上游兼容、原生分发，所以它的规范围绕
IPC / 权限 / Profile / 补丁 / 安装包组织。这个项目完全是另一类东西——**一个人用的本地小工具**，
真正的风险只有两个：

1. **只有一份真实数据**（投递 + 宣讲会 + 进展 + 备忘录，弄坏就没了）；
2. **三个大文件改起来心虚**（当时 `server.py` 3749 行、`index.html` 4105 行、`launcher.py` 1463 行；
   2026-09-22 一轮拆下来是 **2874 / 3175 / 1470**，2026-09-24 实测是
   **2711 / 3286 / 1587**，见 `架构.md` 第五节）。

所以规范只围绕这两件事：每条约束都应该能回答「保护什么」和「怎么验证」。

## 二、抄了什么、没抄什么

**抄（三条治理方法）**

| 抄的 | 在这个项目里长什么样 |
| --- | --- |
| 规则分层、单处维护 | 根 `AGENTS.md` 只放导航和通用；外壳的坑放 `AGENTS.md`，自检的坑放 `AGENTS.md` |
| 改动类型 → 固定的验收证据 | 根 `AGENTS.md` 里那张「改动 → 要跑什么」表 |
| 可检查的事交给脚本 | `tools/` 六个自检 + 纯逻辑回归测试（`test_backup.py` 就是新加的那种） |

**不抄（照搬会翻车）**

- 不引入 TypeScript / 打包器 / ESLint / 任何第三方依赖——会破坏「复制文件夹就能用、双击就跑」。
  这个项目的后端至今只用标准库，前端是单个 `index.html`（原生 HTML/CSS/JS，图表用原生 SVG 画）。
- **不设行数硬门禁**。开发工具 自己就写了「不采用统一 600 行上限；按独立职责、状态和清理流程决定拆分，
  避免为行数打散生命周期」，这条直接照用。
- 不做 monorepo / packages 分层；不引入组件库、状态管理、路由别名。
- **不为「整齐」重命名接口或数据结构**——那是纯数据风险、零收益。

## 三、硬约束（这几条不能破）

1. **零依赖**：`server.py` / `launcher.py` / `backup.py` 只用标准库；前端不用框架、不引 CDN。
2. **无构建步骤**：改完 `web/index.html` 保存刷新就该生效，不许出现「要先 build」。
3. **入口路径固定**：`launcher.py` / `server.py` / `web/index.html` 的名字和位置不许动。
4. **数据只走一条路**：写操作 → 写库 → `log_change()` → 返回完整 state。
5. **用户数据只读着改**：`data/` 不许拿真库做实验，要试就复制一份。
6. **文档跟着代码走**：加接口同步 `app/数据接口说明.md`；加自检同步 `tools/README.md`；
   改完更新 `开发记录` 的**更新记录**和 **0.1 交接**章节。

## 四、写法约定

- **注释写「为什么」**：这个项目注释密度高是有意的——踩过的坑、平台的怪行为、用户的原话都值得留下
  （例：为什么启动流程不能用 `urllib` 做健康检查、为什么拖动不能用 `ReleaseCapture + WM_NCLBUTTONDOWN`）。
  光写「这里在判断端口」没有价值，写「端口没人监听时是 timeout 不是 refused，用 urllib 会把启动卡死」才有。
- 新代码沿用相邻代码的风格；**不为格式化去改无关代码**。
- **小修复不捆绑整文件重构**；有独立状态 / 副作用 / 清理流程的能力才抽成模块（`backup.py` 就是这么来的）。
- **异常要有出口**：不写空 `except`；失败要么写日志、要么返回明确结果。
  `backup.py` 的「失败不拦启动、原因写 `logs/backup.log`」就是这个模式。
- 跨语言的字符串约定（页面的 `shSend("...")` ↔ 启动器的 `ShellApi.handle()`）没有编译期检查，
  只能靠 `tools/verify_shell.js` 里那条静态检查兜着——改这两边要同时改。

## 五、改动的验证要求

见根 `AGENTS.md` 的「**改动 → 要跑什么**」表，这里不复制（单处维护）。
